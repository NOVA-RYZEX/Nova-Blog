# Contributing to Novaryzex

Thank you for contributing to Novaryzex.

Novaryzex is a Git-native blogging platform. That means every contribution should be easy to review, easy to maintain, and aligned with the file-based content workflow.

## Before you start

Please read:

- `README.md`
- `docs/writing-guide.md`
- `docs/folder-structure.md`
- `docs/review-process.md`
- `docs/seo-guidelines.md`

## Contribution types

You can contribute in several ways:

- write a blog post
- improve an existing article
- add or update author metadata
- improve documentation
- fix a UI or accessibility issue
- strengthen validation or build tooling
- improve SEO, layout, or component quality

## Branching workflow

1. Create a new branch from `main`.
2. Make your changes in a focused way.
3. Keep each pull request small when possible.
4. Run local checks before opening the PR.
5. Open the PR with a clear title and description.
6. Respond to review comments.
7. Merge only after checks pass.

## Writing rules

When adding or editing content:

- follow the required folder structure
- include all required frontmatter fields
- keep the article focused on one topic
- use clear headings and readable sections
- add alt text for every image
- use approved MDC components only
- avoid unnecessary formatting noise
- make sure the title, description, and slug are consistent

## Commit message style

Use clear, descriptive commits.

Examples:

- `docs: add writing guide`
- `content: add blog post on access control`
- `fix: correct author metadata`
- `feat: add callout component`

## Pull request expectations

A good pull request should:

- explain what changed
- explain why it changed
- mention any related issue or discussion
- include screenshots if the UI changed
- note any content or SEO impact

## Review standards

We review for:

- correctness
- clarity
- structure
- accessibility
- SEO quality
- maintainability
- consistency with the project voice and style

## Code of conduct

Be respectful, constructive, and collaborative.

## Questions

If a contribution is unclear, open an issue or ask in the pull request before making large changes.
